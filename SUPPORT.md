# Getting help

Start with [getting started](docs/GETTING_STARTED.md), [fine-tuning](docs/FINE_TUNING.md), and [known boundaries](docs/ROADMAP.md).

For a bug report, include your source revision, Python/PyTorch versions, device, minimal input/configuration, exact traceback, and expected behavior. Remove tokens, personal data, private paths, and proprietary weights.

Use issues for reproducible bugs and focused feature proposals. Use discussions for questions when the repository has them enabled. See [SECURITY.md](SECURITY.md) for private vulnerability reporting.
